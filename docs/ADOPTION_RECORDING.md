# 低开销采用记录

## 记录约定

在适用的 AGENTS.md 中加入以下短规则，不需要每个技能重复加入，也不要求模型在聊天中额外解释记录动作。

> 有 `record_skill_use` 工具时，实际采用 Skill 后就近合批记录：`skills` 每项记一次，重复采用保留重复项；`id` 每批唯一且至少16字符，失败重试沿用。只读审计不记，不跨日、不等对话结束才提交；不发送任务正文，不为记录额外解说。工具不可用不伪造补记；记录失败不阻断任务。

批次 ID 推荐 UUID。若技能重名，使用 `插件目录名:技能名`；仍有多个版本时使用准确的 SKILL.md 路径。服务解析后只存标识、必要的来源信息与原始引用列表的 SHA-256 摘要，不保存输入路径明文或任务正文。

例如同一批采用 A 两次、B 一次，`skills` 应包含三个元素。每次重新采用生成新的批次 ID；同一采用的网络重试必须沿用原 ID 与列表。读取说明、审计、浏览清单不等于采用。

## 成本和精确性

工具仅返回 `OK`；时间、插件归属、按日汇总、排名和去重均在本地计算。相邻采用合批节省工具往返，但不合并次数。不等待整个对话结束，以免中断漏记或跨日错位；日期按提交记录的时间计算。

成本仍包含短规则、工具说明与调用参数，不能承诺零 token 或固定 token 数。记录依赖助手执行约定，不是宿主独立检测；未接入的客户端和漏报不可追溯。

新批次先核对请求摘要，已成功的同 ID、同列表重试不再扫描技能清单、不重写台账，技能被移除或出现重名也不影响。列表顺序、引用写法、重复次数必须保持不变；同 ID 的不同内容拒绝覆盖。升级前未保存摘要的旧批次仍按原有技能 ID 核验，不推断当时未保存的原始引用。

采用记录使用排他锁、临时文件原子替换与 32 MiB 容量限制。新锁先写完整的 PID、主机、随机 token 和时间，再用同目录硬链接独占发布，避免创建空锁后进程退出；文件系统必须支持硬链接，不支持时保留台账并拒绝写入。只有同机锁的 PID 明确不存在时才恢复，不按锁龄判断。原 token 对应的独占恢复标记会阻止多个恢复者误删新写者的锁。

活进程、无法确认的进程、其他主机、旧空锁、损坏锁和已有恢复标记均保留。若恢复进程也异常退出并留下标记，先关闭使用该台账的服务并核查标记所有者，备份后只移除已确认失效的对应标记/锁；不能在服务写入期间直接删除。失败重试必须沿用原 ID，不能换 ID 盲目重试。

进程恰好在候选文件发布与清理之间退出时，可能留下 `.tmp` 旁文件；它不参与后续锁判定或统计，恢复过程不擅自清理无法核验归属的文件。

## 启用与验收

构建后重新加载 MCP 服务，确认工具清单出现 `record_skill_use`。全局规则按 [官方 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md) 加载；已有会话是否收到新规则以实际上下文为准。工具尚未出现时不能认为采集已启用。

默认面板显示采用次数。历史信号可单独切换查看，二者不相加。记录前的日历保持未知，首次真实采用后才出现真实数据；不要向正式记录写入验收样例。

测试使用隔离临时目录，覆盖批内重复、新批次累加、卸载后重试、ID 内容冲突、歧义名称、损坏文件、活进程保护、持锁子进程退出、多个子进程恢复竞争和冷启动恢复。测试通过不代表真实宿主已加载新实现或侧栏已完成视觉验收；运行中的旧服务在下次正常重载时加载后端优化。
