# 本地侧栏原型验证

目前采用 Codex 原生 MCP 注册验证入口，尚未提供插件市场安装包。这一步验证当前桌面版本是否发现 global 入口；通过前不宣称侧栏可用。

## Windows 开发安装

先在仓库根目录运行：

```powershell
npm.cmd ci --ignore-scripts
npm.cmd test
$nodeExecutable = (Get-Command node).Source
$managerEntry = (Resolve-Path ./src/server.mjs).Path
codex mcp add codex-skill-manager -- $nodeExecutable $managerEntry
codex mcp get codex-skill-manager
```

不要删除或移动此工作目录；配置引用其中的服务和构建产物。原型只读扫描技能元数据和插件 manifest，不读取会话或凭据，不需要 API 密钥。更新服务代码后需要重新加载 MCP 服务；可通过退出并重开桌面应用完成。

## 宿主验收

保存当前工作后退出并重新打开 Codex 桌面应用。检查侧栏是否能找到“能力管理器”或对应服务入口。记录：是否出现、是否能固定、点击能否显示页面、页面是否收到真实清单、再次重启是否保留。

更新时先运行 `npm.cmd test` 完成构建，再重新加载服务；关闭旧能力管理器面板，从侧栏重新打开。当前 UI 资源地址含页面内容哈希，构建变化会产生新地址。如果仍看到 `PROTOTYPE` 而不是 `READ ONLY`，说明旧页面或旧服务仍在使用，不能视为升级成功。

加入归档功能后的页面标题标识为 `LOCAL`，同时显示“扫描只读”和“归档与恢复记录”。`READ ONLY` 是此前清单版的标识；不要只凭标题判断所有新工具均已加载。

如果没有入口，保留版本号与 MCP 连接状态；不要改隐藏开关。MCP 工具能调用或资源能读取，并不能证明侧栏功能已通过。

本地注册命令不会自动重启桌面应用。重启由用户执行，避免中断其他进行中的工作。

## 撤销开发安装

```powershell
codex mcp remove codex-skill-manager
```

然后重启桌面应用。该命令只移除服务配置，不删除项目文件。安装、查询和移除必须在同一用户配置环境中运行。

## 使用信号索引

“增量导入本机使用信号”读取当前用户的 `sessions` 和 `archived_sessions`。普通技能扫描不读日志。每次至多 32 MiB；页面中的剩余字节不为零时，继续导入或等待正在写入的末行完成。时间范围是已读记录的最早/最晚时间，不保证中间每个会话都完整覆盖。读取失败文件本次不计入统计，问题列表会说明。

索引仅在项目 `.local/usage-index.json`，不保存原文；这是本机私有运行文件，不要提交或上传。文件截断、身份变化及首尾边界变化会触发重建；不提供已读中段任意改写的完整检测保证。

若导入提示被占用，先确认没有正在运行的导入。只有确认上次进程异常退出后，才移除 `.local/usage-index.json.lock`。若索引损坏或需完整重算，保留原索引并将它移到另一个本地备份名称，再点击导入从头读取。不要删除源会话日志。索引达到 64 MiB 时会拒绝覆盖原索引，需要迁移存储后继续。

## 用户技能归档与恢复

仅支持 Windows 下两个用户技能根目录的直接子目录，不修改系统技能、插件缓存或启停配置。先预览，核对范围后执行。归档移动使用 Windows 原生目录重命名；测试已验证目标为已有空目录时同样拒绝覆盖。跨文件系统移动失败时不会回退为复制后删除。

归档目录 `CODEX_HOME/skill-manager-archive` 位于技能扫描目录之外，每项包含 `record.json` 和保留原文件的 `skill` 目录。不要手动删除或上传该目录。恢复需原位置为空缺且归档指纹仍一致；同名冲突请先人工处理。

异常退出可能留下 `operation.lock` 或 `pending-*` 记录。先检查是否仍有操作进行；只有确认进程已退出后再处理残留锁。若仅归档位置存在且指纹一致，可重新预览恢复；两处同时存在、两处均不存在或内容已变化时，保留文件并人工检查，程序不会覆盖或自动删除。移动成功但记录更新失败时不能仅凭状态字段断言失败，须核对两处实际文件。卸载 MCP 服务不会删除这些可恢复文件。
