# Codex Skill Manager 发布素材

以下为可复制的宣传文案，尚未代发到社区。所有配图使用合成记录，不代表真实用户或项目的使用量。

## 一句话介绍

Codex Skill Manager：把已记录的 Skill 采用与插件调用变成日期热力图和排名，本地保存，分别统计。

## 社区短帖

**给 Codex 的 Skills 做了一个本地活动面板**

装了很多 Skills，哪些在最近的工作中被采用过？我做了 Codex Skill Manager，把助手主动记录的采用次数和插件工具调用，分别展示成热力图与排名，还能按日期筛选。

它由本地 MCP 服务、活动界面和配套 Skill 组成。记录保存在本机，不需要额外模型服务。需要先接入记录约定；它不是自动监听器，也不会把“没有记录”当成“从未使用”。

v0.1.0 已开源，Apache-2.0。当前提供 Windows 源码安装；配套 Skill 单独安装不会装好 MCP 服务。演示使用合成数据和浏览器宿主，最新版 Codex 原生侧栏交互仍有未验收项。

仓库与安装：https://github.com/zz11ss11zz/codex-skill-manager

欢迎试用后在 Issues 提供脱敏复现步骤：安装是否顺利、统计口径是否清楚、最需要增加什么能力。

## 知乎／掘金／公众号正文

**标题：给 Codex Skills 做一本本地活动账本：热力图、排名与明确的统计口径**

Skills 越装越多后，一个实际问题是：最近的任务里，哪些能力被采用过？光看安装列表回答不了这个问题；日志里出现名字，也不一定代表实际采用。

我做了一个开源工具 Codex Skill Manager。当前 v0.1.0 的界面集中在活动统计：查看日期热力图，在插件调用和 Skill 采用之间切换，并按时间范围查看排名。配套 MCP 工具还支持本机清单查询、备注，以及 Windows 用户技能的可逆归档；这些管理功能目前不在活动页面里。

这个工具最在意的是把不同记录分开。Skill 采用由助手调用记录工具写入；插件调用记录的是尝试次数，失败尝试也包含在内。读取 SKILL.md、提到某个 Skill、实际采用，是不同的事情，不能简单相加。没有覆盖的日期和没有收到的记录，也不能解释成零使用。

记录保存在本机，应用不增加遥测或额外模型服务。用户需要主动接入记录约定；管理器不会在安装后自动监听所有操作，也不会补造过去的使用历史。源码安装需要联网下载依赖，第三方安装工具的数据政策另计。

完整产品是“本地 MCP 服务＋活动界面＋配套 Skill”。先按安装指南注册服务，再按需安装配套 Skill；只执行 Skill 安装命令不会出现完整管理器。当前验证环境为 Windows，其他平台和最新原生侧栏的未验收范围在仓库中公开说明。

演示图中的名称和数据都是合成示例，使用真实界面在浏览器演示宿主中展示。你可以看到切换类型、筛选日期以及排名随范围变化的过程。

项目地址：https://github.com/zz11ss11zz/codex-skill-manager

版本下载：https://github.com/zz11ss11zz/codex-skill-manager/releases/tag/v0.1.0

如果你也有大量 Skills，欢迎从自己的工作流程试用，并在 Issues 留下脱敏的错误与建议。尤其想了解：安装步骤是否清晰、采用与调用的区别是否容易理解、现有统计能否帮助你整理能力库。
