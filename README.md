# Codex Skill Manager · 能力管理器

在 Codex 中查看本机插件与 Skill 清单、使用证据及整理建议。

**开发中。真实清单页面已由用户截图验证；尚未发布稳定版本。** 本项目不是 OpenAI 官方产品。

## 为什么开发

安装的技能越来越多，却很难回答：装了什么、哪些用过、什么场景该用、哪些重复？本项目把这些问题集中在一个管理界面中，目标是在 Codex 侧栏点击打开，而不是每次通过聊天请求生成报表。

## 产品范围

- 本机独立、系统、插件附带及选定项目的 Skill 清单。
- 插件与 Skill 归属、来源和可核实的启用状态。
- 历史日志增量导入与后续使用记录。
- 区分已安装数量、期间使用过的不同技能数量和使用事件数。
- 每条记录保留证据类型，避免把阅读说明、审计或元数据加载误算成执行。
- 重复副本、同名不同内容、低频及功能重叠候选。
- 后续提供受支持的启停、用户技能归档与恢复。

首版不做 Token/费用优化、跨设备账号全量统计或自动删除。

## 统计可信度

| 信号 | 含义 |
| --- | --- |
| 明确用户调用 | 调用意图，不保证执行成功 |
| 宿主激活记录 | 日志明确记录的激活事件 |
| 读取 SKILL.md | 推断信号，可能只是审计，单独展示 |
| Agent 自报 | 单独标识，不能冒充宿主记录 |
| 名称出现、元数据加载 | 不计入调用 |

“未观察到使用”不等于“从未使用”。每个报表必须展示时间范围、数据覆盖和解析限制。历史重放、分叉、重复导入及分段读取需要去重。

## 隐私边界

运行数据留在本机；默认不上传技能正文、聊天内容或遥测。公开仓库只包含代码、文档及合成测试数据。不会扫描密码或令牌存储。日志解析只提取统计所需字段，不复制完整会话。

## 开发与验收

本地原型需要 Node.js 20 或更高版本：

```sh
npm ci --ignore-scripts
npm test
npm run setup:install
npm run setup:check
```

`npm test` 构建 UI 并使用合成临时目录进行扫描器和 stdio MCP 集成测试。`npm start` 运行等待 MCP 客户端连接的进程，不会打开网页。工具调用时只读扫描用户、系统技能目录与插件缓存中的技能元数据；不读取聊天或凭据。构建后的 UI 通过带内容哈希的 `ui://codex-skill-manager/dashboard-<hash>.html` 资源提供，入口工具为 `open_skill_manager`。页面升级后需重新加载服务并从侧栏重新打开，详见本地验证步骤。

当前按文件实例计数；保留同名和相同内容副本，不宣称它们是不同逻辑技能。插件缓存仅显示为候选，不能据此判断安装/启用状态。扫描范围与失败项均在界面中可查，符号链接跳过。默认扫描 `CODEX_HOME/skills`（未设置时为 `~/.codex/skills`）、`~/.agents/skills` 和 `CODEX_HOME/plugins/cache`。

点击“核对插件安装状态”会执行官方 `codex plugin list --json`，可能连接已配置的插件市场。服务需能从 PATH 找到 Codex CLI；也可用 `CODEX_SKILL_MANAGER_CLI` 指定可执行文件路径。查询有 30 秒超时，失败时不改写当前结果。只保留必要状态字段，不上传技能或聊天。匹配依赖插件 ID 和版本；空清单或未匹配不证明未安装，插件已启用也不证明具体技能已被当前会话加载。普通“重新扫描”只扫描本地文件并清除本次安装核对结果。

点击“增量导入本机使用信号”才读取 `CODEX_HOME/sessions` 与 `CODEX_HOME/archived_sessions`，每次最多 32 MiB；可再次点击续读。界面分别展示显式标记和读取请求、已读记录时间范围、待处理字节与失败项，不能把部分覆盖当作完整历史。相同名称对应多个文件时保留歧义。当前不解析宿主激活和 Agent 自报，动态脚本不推断；信号均不证明执行成功。

索引位于项目 `.local/usage-index.json`（Git 忽略），仅保存引用、定位、时间与读取位置，不保存聊天正文。新进程可续读，超过 4 MiB 的单行跳过并计数；未完成末行留到下次。普通刷新清除页面的上次统计，重新导入会从磁盘索引继续。索引上限 64 MiB，异常退出和索引恢复见 [本地验证步骤](docs/LOCAL_SETUP.md)。

Windows 用户技能可点击“预览归档”，检查文件数、体积、原位置和归档位置，再点“执行归档”。归档将整个目录移动至 `CODEX_HOME/skill-manager-archive/<id>/skill`，保留操作记录；可从归档列表预览并恢复。原位置已有内容时拒绝覆盖。预览十分钟过期、取消即失效；执行前后核对全部文件指纹。系统技能和插件缓存不可归档；含链接、超过 50 MiB 或 10000 项的目录暂不支持。归档不能撤回已运行会话加载的内容，不自动修改启停配置。

原型使用维护中的 MCP SDK v1 与匹配的 MCP Apps SDK v1，锁定依赖版本。Node.js 避免引入额外 Python 环境。安装脚本使用官方 CLI 注册，卸载只移除匹配的注册并保留运行数据。隔离 CLI 测试已通过；完整宿主升级和最新按钮交互仍待验证，不应把协议测试当作全部验收。

见 [开发路线](docs/ROADMAP.md)、[验收记录](docs/VALIDATION.md) 和 [安装、升级、卸载与恢复](docs/LOCAL_SETUP.md)。打包采用文件白名单，排除本机索引、会话日志与归档；目前不发布 npm 包或插件市场安装包。

更新后需重新加载服务并从侧栏重新打开页面。当前已确认入口与真实清单显示，统计和管理交互仍待验收。

官方 UI 协议参考：[Plugin Extensions](https://developers.openai.com/plugins/build/extensions)。声明 global 入口不等于宿主一定默认显示；实际兼容性以验收记录为准。
