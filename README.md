# Codex Skill Manager · 能力管理器

在 Codex 中查看本机插件与 Skill 的采用活动、日期热力图和使用量排序。

当前首页仅保留标题、日历热力图、按项目排列的格子热力图和两组排名。清单、搜索、归档、证据明细等页面区域已暂时移除；既有后台工具和本地记录仍保留。页面打开时读取统计，重新可见或获得焦点时刷新，合并同时到来的刷新请求，不进行定时轮询。没有 `record_skill_use` 写入时明确显示“尚未收到采用记录”，不把工具启用、后台工具调用或历史推断混算为采用。

### 独立插件工具调用

新增 `record_plugin_calls` 接口，独立记录插件工具调用尝试，详见 [接入说明](docs/PLUGIN_CALLS.md)。界面可单独选择“插件工具调用”或“Skill 采用次数”。同一调用 ID 去重，新的调用分别计数；失败尝试也计，不等于成功次数。依赖调用方主动记录，并非宿主自动监听；更新后需重载服务。不回填之前的 GitHub 操作。

### 使用活动面板

默认显示执行过程中由助手主动记录的采用次数；历史日志读取请求与显式标记是独立参考视图，不混入采用次数。相邻采用可通过一次工具调用合批，同一技能重复采用保留重复项。同一批次重试沿用 ID，不重复计数；新批次继续累加，不按对话合并。

`record_skill_use` 仅接收 `id` 和 `skills`，由本地程序补时间并解析唯一归属，成功仅返回 `OK`。采用记录存入 `.local/adoptions.json`，不保存聊天正文；没有额外模型服务或网络请求。首次使用前需加载简短记录约定（见 [采用记录说明](docs/ADOPTION_RECORDING.md)）；该方法依赖助手遵守约定，并非宿主独立验证。工具不可用时不伪造补记，历史缺失保持未知。

首页提供蓝色日历热力图，可切换插件 / Skill、年份和信号类型；悬停、点击或键盘选择日期显示当天计数。下方展示最常用前 5 项和未观测到使用的最多 5 项，项目不足时不补造。排名与热力图使用同一年度与查询期间的交集。

Skill 按文件实例统计；采用与历史信号视图中的插件按所属 Skill 汇总。独立的“插件工具调用”视图支持没有 Skill 的插件，二者不相加。无覆盖日期用斜线标识，未核实的插件缓存不进入零使用列表。采用视图中的“未记录采用”仅表示当前期间没有记录；历史零使用列表要求两类信号都没有观测记录且索引完整。

每日汇总从完整索引计算，不受界面最多 100 条证据的限制。查询按浏览器时区生成每日汇总；首次打开使用服务所在系统时区，实际时区显示在图上。打开面板会只读恢复已有本地索引，无需每次手动查询，不会自动导入新聊天日志。插件默认排在 Skill 前面并选中。宽屏并排排名，窄屏纵向排列，日历可横向滚动。

**开发中。真实清单页面已由用户截图验证；尚未发布稳定版本。** 本项目不是 OpenAI 官方产品。

## 为什么开发

安装的技能越来越多，却很难回答：装了什么、哪些用过、什么场景该用、哪些重复？本项目把这些问题集中在一个管理界面中，目标是在 Codex 侧栏点击打开，而不是每次通过聊天请求生成报表。

## 产品范围

- 本机独立、系统和插件附带的 Skill 清单；首版不扫描项目目录。
- 插件与 Skill 归属、来源和可核实的启用状态。
- 历史日志增量导入与后续使用记录。
- 区分已安装数量、期间使用过的不同技能数量和使用事件数。
- 每条记录保留证据类型，避免把阅读说明、审计或元数据加载误算成执行。
- 重复副本、同名不同内容、低频及功能重叠候选。
- Windows 用户技能归档与恢复，以及本地保留备注；启停配置编辑尚未实现。

首版不做 Token/费用优化、跨设备账号全量统计或自动删除。

## 统计可信度

| 信号 | 含义 |
| --- | --- |
| 用户文本中的显式标记（已实现） | 可能是调用意图或讨论，不保证执行成功 |
| 宿主激活记录（未实现） | 未来仅接受日志明确记录的激活事件 |
| 读取 SKILL.md | 推断信号，可能只是审计，单独展示 |
| 助手采用记录（已实现） | 执行时调用本地记录工具，独立计数，不代表宿主确认或执行成功 |
| 名称出现、元数据加载 | 不计入调用 |

“未记录采用”或“未观察到使用”不等于“从未使用”。报表展示时间范围和数据边界；仅相同事件的重放与重复导入去重，不合并同一对话的不同采用或读取调用。

## 隐私边界

运行数据留在本机；默认不上传技能正文、聊天内容或遥测。公开仓库只包含代码、文档及合成测试数据。不会扫描密码或令牌存储。日志解析只提取统计所需字段，不复制完整会话。

## 开发与验收

本地原型需要 Node.js 20 或更高版本：

```sh
npm ci --ignore-scripts
npm test
npm run setup:install
npm run setup:check
```

`npm test` 构建 UI 并使用合成临时目录进行扫描器和 stdio MCP 集成测试。`npm start` 运行等待 MCP 客户端连接的进程，不会打开网页。构建后的 UI 通过带内容哈希的 `ui://codex-skill-manager/dashboard-<hash>.html` 提供，入口工具为 `open_skill_manager`。构建会原子更新页面并在 `dist/revisions/` 保留新旧版本；服务支持按版本读取，因此全局入口请求被路由到另一会话服务时仍可获取对应 HTML。首次升级到这一修复需要重载旧服务一次。不要在仍有旧页面打开时清理版本文件；服务逻辑改动仍须重载。

当前按文件实例计数；保留同名和相同内容副本，不宣称它们是不同逻辑技能。插件缓存仅显示为候选，不能据此判断安装/启用状态。扫描范围与失败项均在界面中可查，符号链接跳过。默认扫描 `CODEX_HOME/skills`（未设置时为 `~/.codex/skills`）、`~/.agents/skills` 和 `CODEX_HOME/plugins/cache`。

点击“核对插件安装状态”会执行官方 `codex plugin list --json`，可能连接已配置的插件市场。服务需能从 PATH 找到 Codex CLI；也可用 `CODEX_SKILL_MANAGER_CLI` 指定可执行文件路径。查询有 30 秒超时，失败时不改写当前结果。只保留必要状态字段，不上传技能或聊天。匹配依赖插件 ID 和版本；空清单或未匹配不证明未安装，插件已启用也不证明具体技能已被当前会话加载。普通“重新扫描”只扫描本地文件，保留当前服务进程内最近一次安装核对快照；核对时间仍显示为原时间。

点击“增量导入本机使用信号”才读取 `CODEX_HOME/sessions` 与 `CODEX_HOME/archived_sessions`，每次最多 32 MiB；可再次点击续读。界面分别展示显式标记和读取请求、已读记录时间范围、待处理字节与失败项，不能把部分覆盖当作完整历史。相同名称对应多个文件时保留歧义。历史解析不推断宿主激活或助手声明；执行时的采用记录使用独立账本。动态脚本不推断，历史信号均不证明执行成功。

索引位于项目 `.local/usage-index.json`（Git 忽略），仅保存引用、定位、时间与读取位置，不保存聊天正文。新进程可续读，超过 4 MiB 的单行跳过并计数；未完成末行留到下次。普通刷新保留最近一次统计快照，不读取新日志；归属以该次导入时的清单为准。重新导入会从磁盘索引继续，重启服务后可查询已有索引展示统计；若索引缺少覆盖快照，则先导入一次。索引上限 64 MiB，异常退出和索引恢复见 [本地验证步骤](docs/LOCAL_SETUP.md)。

Windows 用户技能可点击“预览归档”，检查文件数、体积、原位置和归档位置，再点“执行归档”。归档将整个目录移动至 `CODEX_HOME/skill-manager-archive/<id>/skill`，保留操作记录；可从归档列表预览并恢复。原位置已有内容时拒绝覆盖。预览十分钟过期、取消即失效；执行前后核对全部文件指纹。系统技能和插件缓存不可归档；含链接、超过 50 MiB 或 10000 项的目录暂不支持。归档不能撤回已运行会话加载的内容，不自动修改启停配置。

原型使用维护中的 MCP SDK v1 与匹配的 MCP Apps SDK v1，锁定依赖版本。Node.js 避免引入额外 Python 环境。安装脚本使用官方 CLI 注册，卸载只移除匹配的注册并保留运行数据。隔离 CLI 测试已通过；完整宿主升级和最新按钮交互仍待验证，不应把协议测试当作全部验收。

见 [开发路线](docs/ROADMAP.md)、[验收记录](docs/VALIDATION.md) 和 [安装、升级、卸载与恢复](docs/LOCAL_SETUP.md)。打包采用文件白名单，排除本机索引、会话日志与归档；目前不发布 npm 包或插件市场安装包。

更新后需重新加载服务并从侧栏重新打开页面。当前已确认入口、真实清单和导入结果显示；日期查询已由用户反馈验证；备注、候选及管理操作的最新版侧栏交互仍待验收。

官方 UI 协议参考：[Plugin Extensions](https://developers.openai.com/plugins/build/extensions)。声明 global 入口不等于宿主一定默认显示；实际兼容性以验收记录为准。


### 按期间查看使用信号

导入后可选择开始和结束日期，点击“查询已有索引”；日期按浏览器本地时区解释，包含起止当天。此操作只读本地索引，不导入新日志。清空日期或点击“全部已索引时间”恢复总量。计数涵盖全部已索引信号，不受界面最多 100 条证据的限制；限定期间时排除时间未知记录。后续导入保持已经应用的期间条件。旧索引若缺少覆盖快照，请先导入一次。期间功能需服务加载包含 `query_usage` 的版本。

清单中的每个文件实例会显示当前统计期间内唯一归属它的两类信号数及最近信号时间。跨类别的“有信号实例数”取并集，不把同一实例重复累加；同名多副本或无法归属的信号不分摊到实例。未观察到唯一归属信号不能作为删除依据。

### 本地保留备注

每个文件实例可记录保留原因或用途差异（最多 1000 字），并标记“低频仍需保留”。备注保存于 Git 忽略的 `.local/skill-notes.json`，不修改技能文件。标记仅为提醒，不改变启停或归档权限；归档仍走独立预览。文件指纹变化时提示重新核对旧备注；并发编辑通过版本号拒绝覆盖。可清空文字并取消勾选以撤回备注。容量上限 4 MiB；损坏文件会保留并禁用编辑。若异常退出留下 `.lock`，先确认没有写入进行，再备份并移除该锁文件。

### 用途重叠候选

“重复与同名冲突候选”中增加描述词语重叠比较。它在本地分词并过滤部分通用词，至少 3 个共同词、交并比至少 0.30 时列为人工核对候选；展示共同词和双方描述。交并比不是置信度，也不代表功能等价。最多比较按实例 ID 排序的 500 个有效描述，每份前 8000 字符、最多 500 个词，显示前 50 对并标明覆盖。否定条件、适用范围和依赖需人工核对，不据此自动删除；同名或相同文档继续使用原有分组。
