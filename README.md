# Codex Skill Manager · 能力管理器

在 Codex 中查看本机插件与 Skill 清单、使用证据及整理建议。

**开发中。尚未发布可用版本；侧栏入口尚待端到端验收。** 本项目不是 OpenAI 官方产品。

## 为什么开发

安装的技能越来越多，却很难回答：装了什么、哪些用过、什么场景该用、哪些重复？本项目把这些问题集中在一个管理界面中，目标是在 Codex 侧栏点击打开，而不是每次通过聊天请求生成报表。

## 产品范围

- 本机独立、系统、插件附带及选定项目的 Skill 清单。
- 插件与 Skill 归属、来源和可核实的启用状态。
- 历史日志增量导入与后续使用记录。
- 区分已安装数量、期间使用过的不同技能数量和使用事件数。
- 每条记录保留证据类型，避免把阅读说明、审计或元数据加载误算成执行。
- 重复副本、同名不同内容、低频及功能重叠候选。
- 后续提供受支持的启停、用户技能归档与恢复。

首版不做 Token/费用优化、跨设备账号全量统计或自动删除。

## 统计可信度

| 信号 | 含义 |
| --- | --- |
| 明确用户调用 | 调用意图，不保证执行成功 |
| 宿主激活记录 | 日志明确记录的激活事件 |
| 读取 SKILL.md | 推断信号，可能只是审计，单独展示 |
| Agent 自报 | 单独标识，不能冒充宿主记录 |
| 名称出现、元数据加载 | 不计入调用 |

“未观察到使用”不等于“从未使用”。每个报表必须展示时间范围、数据覆盖和解析限制。历史重放、分叉、重复导入及分段读取需要去重。

## 隐私边界

运行数据留在本机；默认不上传技能正文、聊天内容或遥测。公开仓库只包含代码、文档及合成测试数据。不会扫描密码或令牌存储。日志解析只提取统计所需字段，不复制完整会话。

## 开发与验收

本地原型需要 Node.js 20 或更高版本：

```sh
npm ci --ignore-scripts
npm test
npm start
```

`npm test` 构建 UI 并进行真实 stdio MCP 集成测试。`npm start` 运行等待 MCP 客户端连接的进程，不会打开网页。当前只提供合成数据；不读取本机技能或聊天。构建后的 UI 通过 `ui://codex-skill-manager/dashboard.html` 资源提供，入口工具为 `open_skill_manager`。

原型使用维护中的 MCP SDK v1 与匹配的 MCP Apps SDK v1，锁定依赖版本。Node.js 避免首个侧栏验证引入额外 Python 环境；持久化与数据库选择留到真实数据阶段。宿主安装配置和插件包尚待实测，不应把协议测试通过当成可安装发布版。

见 [开发路线](docs/ROADMAP.md) 和 [验收记录](docs/VALIDATION.md)。安装命令将在真实验证后补充，不提供未验证的一键安装说明。

官方 UI 协议参考：[Plugin Extensions](https://developers.openai.com/plugins/build/extensions)。声明 global 入口不等于宿主一定默认显示；实际兼容性以验收记录为准。
